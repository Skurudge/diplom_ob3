# Дипломный проект: Сервис обработки загружаемых документов (OB3)

## 📌 Описание проекта
Веб-сервис предназначен для автоматизации процессов загрузки, хранения и верификации документов пользователей. 

**Основной бизнес-процесс:**
1. Зарегистрированный пользователь загружает документ через REST API.
2. Администратор платформы мгновенно получает email-уведомление о новом документе.
3. Отправка писем обрабатывается асинхронно через систему очередей Celery, чтобы не нагружать сайт.
4. Администратор в панели управления Django одобряет или отклоняет документ.
5. Пользователь автоматически получает email-уведомление с результатом проверки.

## 🛠️ Технологический стек
* **Язык программирования**: Python 3.13
* **Фреймворки**: Django 6.0+, Django Rest Framework (DRF) 3.17+
* **База данных**: PostgreSQL
* **Очередь сообщений**: Celery + Redis (версия < 5.0.0)
* **Документация API**: Swagger / OpenAPI (с использованием drf-spectacular)
* **Качество кода**: Контроль типов mypy, форматирование black / isort, проверка PEP8 с flake8
* **Управление пакетами**: Poetry
* **Контейнеризация**: Docker / Docker Compose

## 🚀 Как запустить проект

### 1. Подготовка окружения
Клонируйте репозиторий и перейдите в папку проекта:
```bash
git clone https://github.com/Skurudge/diplom_ob3
cd E:/diplom_ob3
```
Создайте файл `.env` на основе шаблона `.env.example` и укажите в нем свои доступы к локальной базе данных PostgreSQL и SMTP-серверу почты.

### 2. Локальный запуск (Разработка)
Установите зависимости через Poetry, примените миграции базы данных и запустите сервер:
```bash
poetry install
poetry run python manage.py migrate
poetry run python manage.py runserver
```

Для работы писем в отдельном окне терминала запустите воркер Celery:
```bash
poetry run celery -A config worker --loglevel=info
```

### 3. Запуск в Docker (Финальный этап / Для защиты)
Проект можно развернуть одной командой в изолированных контейнерах:
```bash
docker-compose up --build
```

## 📊 Практическая демонстрация (Кейсы для защиты)
Для подтверждения работоспособности сервиса в папку `demo_docs/` добавлены реальные тестовые файлы. На защите диплома демонстрируются два сценария:

1. **Успешный кейс (Файл `case1_pasport.pdf`)**:
   * Пользователь загружает скан паспорта через эндпоинт API `/api/v1/documents/upload/`.
   * Администратор получает email-уведомление.
   * Администратор заходит в Django admin, выбирает документ и нажимает быстрое действие **"Одобрить документ"**.
   * Пользователь получает email с подтверждением. Статус документа меняется на `Одобрен`.

2. **Кейс с отклонением (Файл `case2_invalid.jpg`)**:
   * Пользователь загружает поврежденный или неверный файл.
   * Администратор в панели управления применяет действие **"Отклонить документ"**.
   * Система отправляет пользователю уведомление с требованием загрузить файл повторно. Статус документа меняется на `Отклонен`.
